# MOB-05 직원 개인 스케줄 조회

## 확정 범위

- 직원 역할의 본인 일정만 조회한다.
- 게시(`published`) 및 승인(`approved`)된 일정만 노출한다.
- 주간 기본 화면, 월간 요약, 날짜 상세를 제공한다.
- 명시적 휴무와 일정 없음, 승인 휴가를 구분한다.
- 사업장 시간대와 마지막 동기화 시각을 표시한다.
- 사용자·사업장·조회 기간별 세션 캐시를 사용한다.
- 첫 조회 오류와 기존 데이터 갱신 오류를 구분한다.

## 서버 보안 계약

클라이언트는 `organization_id`, `from`, `to`만 보낸다. 서버가 `auth.uid()`로 `staff_id`를 확정하며 직원 연결이 없으면 `staff_not_linked`로 거절한다. 다른 직원 ID를 입력하는 계약 자체를 제공하지 않는다.

기존 RPC의 `status <> 'cancelled'` 조건은 초안을 노출할 수 있어 `status = 'published' and approval_status = 'approved'`로 강화했다. 승인 휴가만 동일 응답의 `leaves`에 포함한다.

## 후속 범위 구현

- `schedule_revision`과 변경 전후 스냅샷을 저장하고 직원별 확인 revision을 관리한다.
- 변경된 일정은 배지와 이전→현재 비교를 보여주며 `변경 확인`으로 확인 상태를 기록한다.
- 하루 1건 고유 제약을 제거하고, 휴무와 근무의 동시 등록 및 시간이 겹치는 복수 근무는 서버 트리거로 차단한다.
- 겹치지 않는 같은 날 복수 근무는 시간순으로 모두 표시한다.
- 휴가는 `full`, `am`, `pm`을 구분한다. 오전은 13:00 이전, 오후는 13:00 이후 근무와 겹치면 확인 필요 경고를 표시한다.
- Web Push 구독 RPC와 서비스 워커 수신·딥링크를 추가했다. `NEXT_PUBLIC_WEB_PUSH_PUBLIC_KEY`가 있는 배포에서만 직원에게 알림 설정을 노출한다.

푸시 발송 공급자 작업자는 기존 `timefit_user_schedule_notification_outbox`와 활성 구독을 소비한다. 브라우저 구독 비밀값은 서비스 역할만 쓰며 화면/API 응답에 포함하지 않는다.
