# TimeFit 모바일 텍스트·이미지 배치 및 정렬 설계

작성일: 2026-09-30  
문서 상태: 레이아웃 구현 기준안 v1.0  
선행 문서: `130-mobile-app-toss-inspired-uiux-design-2026-09-30.md`  
적용 대상: 직원·매니저·총관리자 모바일 앱

## 1. 결론

TimeFit 화면 정렬은 모든 요소를 가운데 맞추는 방식이 아니라, 사용자가 위에서 아래로 `결론 → 근거 → 행동`을 자연스럽게 읽도록 하나의 왼쪽 기준선과 반복되는 수직 리듬을 유지하는 방식으로 설계한다.

핵심 규칙:

1. 본문 콘텐츠는 기본적으로 왼쪽 정렬한다.
2. 숫자 비교와 금액만 오른쪽 정렬한다.
3. 빈 상태·완료 상태처럼 읽을 정보가 적은 화면만 중앙 정렬한다.
4. 이미지는 장식보다 증거와 맥락을 보여주는 용도로 사용한다.
5. 아이콘, 제목, 설명, 상태, 이동 표시의 위치를 화면마다 바꾸지 않는다.
6. 긴 한국어 문장, 큰 글자, 작은 기기에서도 같은 읽기 순서를 유지한다.

## 2. 레이아웃 기준선

### 2.1 4pt 기반 간격

모든 여백과 크기는 4의 배수를 기본으로 한다.

```text
4  : 아이콘과 짧은 라벨
8  : 제목과 설명, 같은 묶음 내부
12 : 목록 행 내부 요소
16 : 작은 그룹·입력 필드
20 : 모바일 좌우 기본 여백
24 : 카드 내부 여백
32 : 섹션 간격
40 : 큰 화면 결론과 다음 영역
```

예외는 안전영역, 플랫폼 기본 컨트롤, 광학 정렬에만 허용한다.

### 2.2 수평 그리드

| 기기 폭 | 좌우 여백 | 콘텐츠 폭 | 열 |
|---|---:|---:|---|
| 320~359dp | 16dp | 화면-32dp | 4열 |
| 360~599dp | 20dp | 화면-40dp | 4열 |
| 600~839dp | 32dp | 화면-64dp | 8열 |
| 840dp 이상 | 40dp | 최대 960dp | 12열 |

- 모바일 열 간격은 12dp다.
- 태블릿 열 간격은 16dp다.
- 본문, 섹션 제목, 목록 구분선은 같은 콘텐츠 기준선에 맞춘다.
- 배경색이 화면 끝까지 이어지는 영역도 내부 콘텐츠는 기준선을 유지한다.

### 2.3 수직 리듬

- 앱 바 아래 첫 본문 기준선: 16dp
- 눈썹 텍스트와 화면 제목: 8dp
- 화면 제목과 설명: 8dp
- 헤더 설명과 첫 주요 행동: 24dp
- 섹션 제목과 첫 행: 12dp
- 목록 행 사이: 구분선 사용, 별도 외부 간격 없음
- 섹션 사이: 32dp
- 마지막 콘텐츠와 하단 내비게이션: 최소 24dp

## 3. 텍스트 정렬

### 3.1 기본 정렬

| 콘텐츠 | 정렬 | 이유 |
|---|---|---|
| 화면 제목·설명 | 왼쪽 | 빠른 스캔과 한국어 읽기 흐름 |
| 카드 제목·본문 | 왼쪽 | 정보 계층 유지 |
| 버튼 라벨 | 가운데 | 행동 인지 |
| 금액·시간 비교 열 | 오른쪽 | 자릿수 비교 |
| 상태 칩 | 콘텐츠 옆 또는 오른쪽 | 대상과 상태 연결 |
| 빈 상태 | 가운데 | 읽을 정보가 적음 |
| 성공 결과 | 왼쪽 우선, 짧으면 가운데 | 결과와 다음 행동 연결 |

화면 제목을 가운데 정렬하지 않는다. 상단 중앙 제목은 iOS 플랫폼 탐색 맥락이 꼭 필요한 보조 화면에만 사용한다.

### 3.2 텍스트 블록 폭

- 큰 결론 문장: 화면 폭의 최대 90%
- 설명 문장: 화면 폭의 최대 92%, 최대 3줄
- 긴 정책·도움말: 최대 34자 내외의 읽기 폭을 권장
- 버튼: 기본 한 줄, 최대 16자 권장
- 상태 칩: 최대 두 단어, 한 줄

### 3.3 줄바꿈

- 제목은 의미 단위가 유지되도록 자연 줄바꿈한다.
- 이름·사업장명은 글자 단위로 강제 분리하지 않고 한 줄 말줄임을 우선한다.
- 본문은 한국어 글자 단위 줄바꿈을 허용한다.
- 시간 범위 `09:00–18:00`, 금액 `1,250,000원`, 날짜 `9월 30일`은 분리하지 않는다.
- 괄호 안 상태가 다음 줄에 홀로 남지 않게 한다.

### 3.4 숫자 정렬

- 금액, 시간, 근무 인원은 tabular number를 사용한다.
- 단일 KPI는 왼쪽 정렬할 수 있지만 비교 표는 오른쪽 정렬한다.
- 단위는 값과 같은 기준선에 두되 1단계 작은 크기로 표현한다.
- 증가·감소 기호는 숫자 바로 앞에 두고 색상만으로 의미를 전달하지 않는다.

### 3.5 제목 계층

```text
Eyebrow  : 날짜·범위·역할
Title 1  : 화면의 결론 한 문장
Body     : 결론을 이해하는 최소 근거
Title 2  : 다음 섹션의 업무 목적
Row title: 개별 대상·행동
Caption  : 기준 시각·상태·보조 정보
```

한 화면에서 `Title 1`은 한 번만 사용한다.

## 4. 이미지 배치

### 4.1 이미지 사용 원칙

이미지는 다음 중 하나를 충족할 때만 사용한다.

- 증거: 영수증, 첨부 문서, 출퇴근 사진
- 식별: 직원 프로필, 사업장 이미지
- 설명: 권한 요청이나 빈 상태의 간단한 안내
- 결과: 분석 전후 비교가 필요한 이미지

장식만을 위한 대형 이미지는 홈 첫 화면에서 사용하지 않는다.

### 4.2 이미지 비율

| 이미지 | 목록 | 상세 | 처리 |
|---|---|---|---|
| 직원 프로필 | 40×40 또는 48×48 원형 | 64×64 원형 | 중앙 크롭 |
| 영수증 | 4:5 썸네일 | 최대 폭, 원본 비율 유지 | contain, 상단 정렬 |
| 첨부 문서 | 4:3 미리보기 | 원본 비율 | contain |
| 사업장 사진 | 16:9 | 16:9 | cover |
| 빈 상태 일러스트 | 최대 120×120 | 동일 | 전체 노출 |

### 4.3 이미지 정렬

- 프로필 이미지는 행의 첫 번째 텍스트 기준선보다 1~2dp 위로 광학 정렬한다.
- 영수증 상세는 화면 너비에 맞추고 이미지 아래에 추출 결과를 배치한다.
- 모바일에서 원본과 OCR 값을 좌우 2열로 두지 않는다. 위아래로 배치한다.
- 태블릿 600dp 이상에서만 원본 5열, 결과 7열 구조를 허용한다.
- 여러 이미지는 가로 스크롤보다 첫 이미지와 `+N장`을 보여주고 상세 갤러리로 이동한다.
- 이미지 위에 긴 텍스트를 겹치지 않는다.

### 4.4 이미지 로딩·오류

- 로딩 중에는 같은 비율의 중립 스켈레톤을 유지한다.
- 실패 시 빈 이미지 아이콘, 실패 문구, 다시 불러오기 행동을 제공한다.
- 이미지가 없어도 제목·상태·행동은 같은 위치를 유지한다.
- 민감 이미지의 썸네일은 앱 전환 화면에서 흐림 처리할 수 있게 한다.

## 5. 아이콘 정렬

- 기본 아이콘: 20dp
- 주요 행동 아이콘: 24dp
- 목록 상태 아이콘 표면: 40×40dp
- 하단 내비게이션 아이콘: 22dp
- 아이콘과 텍스트: 8dp
- 아이콘 버튼 터치 영역: 최소 48×48dp

아이콘의 외곽 박스가 아니라 실제 시각 중심을 기준으로 광학 정렬한다. 화살표·재생 아이콘처럼 무게중심이 치우친 아이콘은 1dp 안쪽 보정을 허용한다.

오른쪽 이동 화살표는 장식 요소로 처리하고 화면 읽기에서 제외한다.

## 6. 공통 배치 패턴

### 6.1 앱 바

```text
┌────────────────────────────┐
│ 사업장명 ⌄              알림 │
└────────────────────────────┘
```

- 사업장명은 왼쪽 정렬, 알림은 오른쪽 48dp 터치 영역에 둔다.
- 중앙에는 로고나 중복 제목을 넣지 않는다.
- 긴 사업장명은 한 줄 말줄임 처리한다.

### 6.2 페이지 헤더

```text
9월 30일 수요일
오늘은 9시에 근무해요
오픈 근무 · 09:00–18:00 · 휴게 1시간
```

- 세 문장은 같은 왼쪽 기준선을 사용한다.
- 날짜는 보조색, 결론은 가장 큰 글자, 근거는 본문 크기다.
- 제목 옆에 버튼을 두지 않는다. 행동은 다음 영역에 분리한다.

### 6.3 주요 행동 영역

```text
출근 준비가 됐어요
매장 QR을 스캔하면 바로 기록돼요.
[              QR 출근하기              ]
```

- 제목과 설명은 왼쪽, 버튼은 전체 폭을 사용한다.
- 아이콘을 큰 중앙 장식으로 사용하지 않는다.
- 배경 표면은 화면당 하나만 강하게 사용한다.

### 6.4 작업 목록 행

```text
[40 아이콘]  행동형 제목                 [>]
             영향·기한·대상
```

그리드:

```text
40dp + 12dp + flexible + 8dp + 20dp
```

- 행 높이 최소 72dp
- 제목 최대 2줄, 설명 최대 2줄
- 오른쪽에 금액이나 상태가 있으면 이동 화살표 대신 해당 값을 표시한다.
- 프로필 이미지와 상태 아이콘을 동시에 앞에 배치하지 않는다.

### 6.5 사람 목록 행

```text
[48 프로필]  이름 · 직무              상태 칩
             오늘 근무시간
```

- 이름과 직무는 한 줄 안에서 위계를 구분한다.
- 상태 칩은 첫 줄 기준선에 맞춘다.
- 출퇴근 시각은 두 번째 줄 오른쪽이 아니라 설명과 같은 왼쪽 흐름에 둔다.

### 6.6 KPI 행

```text
완료 매출                        30,530,900원
확정 지출                        12,430,000원
```

- 라벨은 왼쪽, 값은 오른쪽 정렬한다.
- 여러 KPI를 작은 카드로 분리하지 않는다.
- 중요 합계는 마지막 행의 위쪽 구분을 강화한다.
- 기준 시각은 목록 아래 왼쪽에 둔다.

### 6.7 입력 폼

```text
필드 라벨
[ 입력값                               ]
도움말 또는 오류
```

- 라벨은 항상 필드 위에 둔다.
- placeholder를 라벨로 사용하지 않는다.
- 필드 간 20dp, 같은 그룹 내부는 12dp를 사용한다.
- 오류 문구는 해당 필드 바로 아래 왼쪽 정렬한다.
- 모바일에서 라벨과 입력을 좌우로 배치하지 않는다.

### 6.8 비교 정보

```text
변경 전  09:00–18:00
변경 후  13:00–21:00
```

- 라벨 열은 64dp 고정, 값은 왼쪽 정렬한다.
- 취소선에만 의존하지 않는다.
- 승인 상세에서 원본과 요청값을 좌우로 놓지 않고 위아래로 비교한다.

### 6.9 하단 고정 행동

- 스크롤 콘텐츠 아래에 96dp 이상의 여유를 둔다.
- 안전영역 포함 높이는 플랫폼에 맞춘다.
- 주 행동 1개는 전체 폭, 보조 행동은 텍스트 버튼으로 둔다.
- 승인/반려가 동등한 선택이면 2열을 사용할 수 있다.
- 키보드가 열리면 현재 필드와 CTA가 동시에 보이게 조정한다.

## 7. 화면별 배치 설계

### 7.1 직원 홈

```text
앱 바
페이지 헤더
주요 출퇴근 영역
확인 필요 목록
빠른 업무 3열
이번 주 요약
하단 내비게이션
```

- 첫 화면에 인사말 이미지나 프로필 이미지를 크게 배치하지 않는다.
- 빠른 업무 아이콘은 같은 크기와 기준선을 사용한다.
- 화면 제목과 출퇴근 영역 사이에 다른 카드가 끼어들지 않는다.

### 7.2 매니저 홈

```text
앱 바
운영 결론
직원 상태 4열 숫자
우선 처리 목록
인원 부족 영역
미확인 변경
```

- 상태 숫자는 같은 폭으로 정렬하지만 별도 카드로 만들지 않는다.
- 우선 처리 목록이 숫자보다 먼저 필요하면 역할 설정에 따라 위치를 교체한다.
- 직원 프로필은 상세 진입에 도움이 될 때만 표시한다.

### 7.3 총관리자 홈

```text
앱 바
운영 결론
가장 중요한 업무 1개
경영 KPI 행
데이터 기준 시각
웹 관리자 연결
```

- 금액은 오른쪽 끝을 맞춰 자릿수를 비교할 수 있게 한다.
- 네 개 금액을 2×2 카드로 배치하지 않는다.
- 시스템 문제와 사람의 할 일을 같은 경고 영역에 섞지 않는다.

### 7.4 영수증 확인

```text
앱 바 / 뒤로가기
처리 상태와 수정 요청
영수증 원본 4:5
다시 촬영·확대
추출 결과 목록
문제 필드
하단 재제출 CTA
```

- 원본은 첫 화면 폭을 사용하되 높이가 지나치게 길면 최대 높이와 확대 보기를 제공한다.
- OCR 값은 원본 위에 겹치지 않는다.
- 문제 필드는 일반 필드보다 먼저 표시할 수 있지만 같은 왼쪽 기준선을 사용한다.
- 여러 영수증 페이지는 상단 썸네일 띠보다 `1/3`과 이전·다음 제어를 권장한다.

### 7.5 승인 상세

```text
요청 유형·기한
결론 한 문장
신청자 행
변경 전·후
스케줄·잔여·충돌 근거
처리 이력
하단 승인/반려
```

- 신청자 프로필은 40dp, 이름과 부서는 왼쪽 정렬한다.
- 상태 칩은 화면 제목 옆이 아니라 요청 메타 영역에 둔다.
- 변경 비교와 근거를 카드 안에 다시 카드로 중첩하지 않는다.

### 7.6 급여명세

- 실지급액은 왼쪽 정렬하고 통화 단위를 같은 줄에 둔다.
- 지급·공제 목록의 항목명은 왼쪽, 금액은 오른쪽 정렬한다.
- 소계는 상단 여백과 굵기로 구분하고 색상을 과도하게 사용하지 않는다.
- 근무 근거는 별도 상세 행으로 연결한다.
- 전월 비교는 변화 금액 뒤에 원인 문장을 배치한다.

## 8. 반응형 재배치

### 8.1 320dp

- 좌우 여백 16dp
- 빠른 업무 3열 유지, 라벨은 최대 2줄
- KPI는 한 행씩 세로 배치
- 상태 숫자 4열은 2×2로 전환 가능
- 제목이 3줄을 넘으면 문구를 축약한다.

### 8.2 360~599dp

- 기본 모바일 사양 적용
- 작업 행은 아이콘·본문·보조값 3열
- 영수증과 결과는 세로 배치

### 8.3 600~839dp

- 승인함: 목록 5열 + 상세 3열 또는 목록/상세 40:60
- 영수증: 원본 5열 + 결과 7열
- 홈은 최대 640dp 콘텐츠 폭으로 중앙 배치

### 8.4 840dp 이상

- 콘텐츠 최대 960dp
- 홈은 7:5 비율의 주 업무·보조 정보 2열 가능
- 하단 내비게이션은 사이드 레일로 전환 가능
- 공용 태블릿 키오스크 레이아웃과는 별도 유지

## 9. 정렬 예외

### 중앙 정렬 허용

- 첫 가입 완료
- 출퇴근 성공 결과
- 데이터가 없는 정상 빈 상태
- 전체 화면 권한 안내

중앙 정렬 화면에도 다음 행동은 전체 폭 하단 CTA를 우선한다.

### 오른쪽 정렬 허용

- 금액
- 시간 합계
- 비교 수치
- 목록의 짧은 보조 상태

긴 문장과 다중 상태를 오른쪽 정렬하지 않는다.

### 전체 폭 이미지 허용

- 영수증 원본
- QR 카메라
- 문서 미리보기

장식 이미지와 직원 프로필은 전체 폭으로 사용하지 않는다.

## 10. 이미지·텍스트 접근성

- 의미 있는 이미지에는 결과 중심 대체 텍스트를 제공한다.
  - `김민지 프로필 사진`
  - `총액 32,000원이 표시된 영수증 원본`
- 장식 이미지는 화면 읽기에서 제외한다.
- 이미지 위 텍스트는 사용하지 않는 것을 기본으로 한다.
- 큰 글자에서 이미지가 텍스트 공간을 침범하면 이미지보다 텍스트를 우선한다.
- 이미지 확대 화면에서 회전, 확대, 닫기 버튼을 명확히 제공한다.
- 프로필 사진이 없어도 이름과 소속으로 사용자를 식별할 수 있어야 한다.

## 12. 구현 규칙

- 화면별 임의 padding을 추가하지 않고 공통 PageScaffold가 좌우 여백을 소유한다.
- Section 컴포넌트가 제목과 콘텐츠 사이 간격을 소유한다.
- ActionRow가 아이콘·텍스트·보조값의 열 크기를 소유한다.
- 텍스트 위젯에서 임의 높이를 고정하지 않는다.
- 이미지 영역은 aspect ratio와 최대 높이를 함께 정의한다.
- 화면마다 다른 아이콘 크기를 사용하지 않는다.
- 숫자 정렬은 폰트 기능과 정렬 규칙을 공통 컴포넌트에서 처리한다.
- SafeArea와 키보드 inset은 화면이 아니라 공통 셸에서 처리한다.

## 13. 정렬 QA 체크리스트

### 텍스트

- 화면의 주요 텍스트가 같은 왼쪽 기준선을 사용하는가?
- 제목, 설명, 행 제목의 위계가 크기와 간격으로 구분되는가?
- 금액과 시간 비교 열의 오른쪽 끝이 맞는가?
- 긴 사업장명·직원명·한국어 문장이 깨지지 않는가?
- 200% 글자 크기에서 버튼과 상태가 겹치지 않는가?

### 이미지

- 이미지가 없어도 레이아웃이 무너지지 않는가?
- 영수증 원본이 잘리지 않고 확대 가능한가?
- 프로필 크기와 텍스트 기준선이 모든 목록에서 같은가?
- 장식 이미지가 주요 행동보다 먼저 보이지 않는가?
- 이미지 로딩·실패 상태가 같은 비율을 유지하는가?

### 컴포넌트

- 목록 행의 아이콘, 제목, 설명, 보조값 열이 일관적인가?
- 카드가 중첩되지 않는가?
- CTA가 콘텐츠 기준선과 일치하는가?
- 하단 CTA와 마지막 콘텐츠가 겹치지 않는가?
- 320dp에서 가로 스크롤이 생기지 않는가?

## 14. 프로토타입 검증 기준

| 화면 | 검증 포인트 | 합격 기준 |
|---|---|---|
| 직원 홈 | 제목→출근 행동 시선 흐름 | 3초 내 주요 행동 발견 |
| 매니저 홈 | 숫자와 작업 목록 우선순위 | 5초 내 첫 처리 대상 선택 |
| 총관리자 홈 | 금액 자릿수 비교 | 네 지표를 오독 없이 비교 |

## 15. 최종 배치 원칙

TimeFit의 정렬은 화면을 정돈하는 장식 규칙이 아니라, 사용자가 실수 없이 업무를 완료하게 하는 기능이다.

- 같은 의미는 항상 같은 위치에 둔다.
- 결론과 행동을 이미지보다 먼저 배치한다.
- 숫자는 비교할 수 있게, 문장은 읽을 수 있게 정렬한다.
- 모바일에서는 원본과 상세를 좌우로 압축하지 않는다.
- 이미지가 사라져도 업무 흐름이 유지되어야 한다.
- 정렬을 위해 글자 크기나 터치 영역을 줄이지 않는다.
